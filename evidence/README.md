# Captured evidence

Every file here was read from the live retail unit, not reconstructed from
documentation. `porting.toml` cites these paths, and
`scripts/porting-record.py check` fails if a cited path is missing, so this
directory is the anchor for the whole record.

The 27-partition backup (981 MB) is deliberately **not** committed. It stays
offline; `evidence/block-sizes.txt` records the geometry it was taken from.

`uefi/dtb/rmx3823.dtb` (805,135 B) is the merged result of
`kalama-base.dtb` + `zonda-B.dtbo`, i.e. the FDT the phone actually boots
with. It is kept under `uefi/` rather than here because the firmware overlay
consumes it.

## How it was captured

Read-only throughout; nothing was written to the device.

```sh
adb shell su -c 'cat /proc/cmdline'        > cmdline.txt
adb shell su -c 'cat /proc/iomem'          > iomem.txt
adb shell su -c 'cat /proc/partitions'     > partitions.txt
adb shell su -c 'dmesg'                    > dmesg.txt
adb shell su -c 'ls -l /dev/block/by-name' > by-name.txt

# The live merged FDT, and the two inputs that produce it.
adb shell su -c 'cp /sys/firmware/fdt /sdcard/fdt.bin' && adb pull /sdcard/fdt.bin
adb shell su -c 'dd if=/dev/block/by-name/vendor_boot_a of=/sdcard/vb.img' && adb pull /sdcard/vb.img
adb shell su -c 'dd if=/dev/block/by-name/dtbo_a         of=/sdcard/dtbo.img' && adb pull /sdcard/dtbo.img
```

`block-sizes.txt` is the join of `by-name.txt` with the kernel's block counts,
because `/proc/partitions` reports `sde13`-style names rather than GPT labels.

`board-facts.md`, `reserved-memory.txt` and `memorymap-generated.c` come from
`analyze-dump.py` run over this directory. `uefi-img-drivers.txt` comes from
walking the firmware volume in the stock `uefi_a` partition: FV at `0x1000`,
length `0x300000`, header `0x48`, 183 FFS entries, 107 of them PE32.
